## База данных

Модуль использует реляционную базу данных **PostgreSQL**. Для работы с ней в коде используется **SQLAlchemy 2.0** (ORM), а для управления миграциями — **Alembic**. 

### Архитектурный подход к данным
Модуль спроектирован так, чтобы работать автономно, но при этом легко интегрироваться в основную систему инженерной школы. 
Для этого не используются прямые внешние ключи (FK) на таблицы основной системы. Вместо этого в таблицах предусмотрены «внешние идентификаторы» (`external_project_id`, `external_student_id`, `external_user_id`). Это позволяет на первом этапе создавать данные локально, а при интеграции — просто сопоставить их с реальными ID из внешней системы без перестройки всей модели.

### Основные сущности (Таблицы)
Схема БД разделена на несколько логических блоков:

1. **Пользователи и доступ:**
   * `module_users` — учетные записи администраторов и экспертов (жюри). Поддерживает как локальную авторизацию (`auth_provider = 'local'`), так и интеграцию с единым входом школы.
2. **Конкурсы и проекты:**
   * `competitions` — карточка конкурса (название, даты, статус, дедлайн ответов).
   * `competition_projects` — проекты, участвующие в конкретном конкурсе.
   * `competition_participants` — участники конкурса (привязка человека к проекту). Один человек может участвовать в разных конкурсах, но только в одном проекте каждого конкурса.
3. **Жюри и критерии:**
   * `competition_judges` — состав жюри конкретного конкурса.
   * `judge_project_assignments` — закрепление конкретных экспертов за конкретными проектами.
   * `evaluation_criteria` — настройка критериев и максимальных баллов для каждого конкурса.
4. **Оценивание и обратная связь:**
   * `evaluation_forms` — бланки оценивания (один бланк = один эксперт + один проект). Поддерживает статусы черновика и отправки.
   * `evaluation_scores` — баллы, выставленные экспертом по каждому критерию.
   * `evaluation_questions` — вопросы, которые эксперты задают участникам по критериям.
   * `evaluation_answers` — письменные ответы участников на вопросы жюри.
   * `answer_awards` — дополнительные баллы, которые жюри начисляет за ответы (учитываются в личном результате участника, но не в итоговом балле проекта).
5. **Аудит:**
   * `evaluation_audit_log` — журнал действий (кто, когда и что изменил). Записи в этом журнале защищены от изменения и удаления.
